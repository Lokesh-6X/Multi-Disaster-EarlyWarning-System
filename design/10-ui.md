# 10. User Interface

Pages, layout, wireframes, components, charts, real-time behaviour and navigation by role for the React dashboard. Requirements: [07](../requirements/07-web-application.md) (§7.2 pages, §7.3 visibility, WEB-01 – WEB-08, WEB-20 – WEB-26), NFR-04, NFR-06. API: [02](02-api.md). Performance architecture: [13](13-frontend-performance.md).

Decisions referenced: DD76–DD81 in [decisions.md](decisions.md).

## 10.1 Principles

| Principle | Rule |
|---|---|
| Alert state first | The alert banner is on every page and is the first thing rendered ([13 §13.3.7](13-frontend-performance.md)) |
| Never colour alone (DD77) | Levels always shown as colour **+ text + icon** (`▲ ORANGE WARNING`), WCAG AA contrast, so colour-blind users and grey-scale printouts work |
| Honest freshness | Every value shows its age; stale and degraded data is marked ([13 §13.3.8](13-frontend-performance.md)) |
| Site time | All times in the site timezone with its label (e.g. "14:05 IST") (NFR-06) |
| Backend decides | The UI hides what a role cannot do, but every check is also on the server (WEB-21) |
| Desktop only (DD80, requirements D34) | The dashboard is used on the server machine (the control PC), not on phones or other computers; layouts target a desktop screen |
| Light and dark | Follows the system setting; IMD colours tuned for both |

| Element | Behaviour |
|---|---|
| Connection pill | `● Live` / `◌ Reconnecting in 5 s` / `◐ Polling` (degraded mode) ([13 §13.3.8](13-frontend-performance.md)) |

- Cells are shaded by probability and outlined at the Watch / Warning cut-offs.
- A `degraded` kit forecast shows a banner "Part of the last 7 days filled from Open-Meteo (5 h)"; a `skipped` kit shows "No forecast: no data since …" ([07 §7.4](07-forecast-worker.md)).
- Runs are cached by ID, so previous/next/compare are instant ([13 §13.3.3](13-frontend-performance.md)).

### 10.4.6 Users, audit, notifications (admin)

Tables with filters and cursor-based infinite scroll ([13 §13.3.6](13-frontend-performance.md)). Users: name, email, role, state, last login, invite email status (with the hint "the invite link opens only on this PC", D34), actions (invite, resend, change role, deactivate/reactivate with reason; the last-admin and own-role rules shown as disabled buttons with a tooltip, WEB-05). Bulk invite: CSV upload with a per-row result table (WEB-07).

### 10.4.7 Model reports (`/reports`)

```
[ Accuracy ] [ Hazard skill ] [ Back-tests ] [ Explainability ] [ Live verification ]
Accuracy: MAE by horizon — lines for TFT-NWP, TFT-base, Open-Meteo, LightGBM, Chronos-Bolt, persistence; variable selector
Hazard skill: per event: Brier, PR-AUC, recall/precision/false alarms at Watch and Warning cut-offs; reliability diagram; events without a classifier say "not enough events to train" and which probability source is used instead
Back-tests: top-10 events per hazard: date, peak, first Watch / Warning, lead time; "would have warned" ✓/✗
Explainability: TFT variable importance bars (static / past / future); SHAP top-20 per classifier
Live verification: MAE per horizon from stored runs vs kit data (once enough data exists); before/after fine-tuning
```

## 10.7 Real-time behaviour

| Event | Visible effect |
|---|---|
| `reading.new` | Tiles and sparklines update; freshness resets |
| `kit.status` | Badge changes; offline tiles grey out with "No data for …" |
| `alert.changed` | Banner, lists and detail update; escalations flash the banner once and play the sound (if on) |
| `alert.acknowledged` | "✓ Priya 12:40" appears for everyone |
| `forecast.run_completed` | Forecast page shows "New run 14:15 — view" (does not jump while the user reads an older run); dashboard strip updates |
| `config.changed` | Admin pages reload the changed record; others get a small notice |
| `system.status` | Shell warning |
| Disconnect | Connection pill, freshness labels count up, degraded polling after 3 failed reconnects |

## 10.8 Error handling

| Problem `code` | UI |
|---|---|
| `SESSION_EXPIRED`, `UNAUTHENTICATED`, WebSocket `4401` | Redirect to login, then back to the same page |
| `FORBIDDEN` | "You do not have access" page (should not happen through normal navigation) |
| `VALIDATION_FAILED` | Messages next to fields |
| `CONFIG_VERSION_CONFLICT` | `VersionConflictDialog` |
| `RATE_LIMITED` | Toast with retry time |
| `SERVICE_UNAVAILABLE`, `INTERNAL_ERROR` | Toast with `request_id`; data stays on screen marked stale |
